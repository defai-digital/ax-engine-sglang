# Qwen3.8-27B NVFP4 RTX PRO 6000 retest

Qwen3.8-27B NVFP4 served on one RTX PRO 6000. AR and both DFlash2
routes passed mixed requests, cancellation and request-pool reuse. Recurrent
GDN passed bit-exact kernel replay. The greedy comparison matched four of
seven prompts for each DFlash2 route, and the recurrent profile failed four
of 28 sampled distribution checks.

The [follow-up RTX verification report](2026-11-19-rtx-nvfp4-parity.md) covers the FP8 projection diagnosis and the opt-in profile with a matched AR reference.

## Environment and controls

- NVIDIA RTX PRO 6000 Blackwell Server Edition, SM120, 97,887 MiB of VRAM,
  driver 595.112.07. SGLang 0.5.23, PyTorch 2.14.1+cu130, FlashInfer 0.7.2,
  Triton 3.8.0 and Transformers 5.19.0.
- The initial run used `6b0df5d` and the [same pinned checkpoints and tokenized
  prompts as the B200 follow-up](2026-11-18-b200-27b-nvfp4.md). The three target
  shard SHA-256 hashes matched the checkpoint manifest. The DFlash2 snapshot
  was downloaded at its pinned revision and its weight SHA-256 was recorded.
- Full attention used FlashInfer and the NVFP4 GEMM backend was FlashInfer
  CUTLASS. The target KV cache used FP8 E4M3 and the draft used BF16. Decode
  and verify graphs used two request slots, a 4,096-token context limit, and
  an 8,192-token KV pool. Tree width was 16 and chain width was eight.
- Greedy compared exact token IDs for seven frozen prompts with a 32-token
  output budget. The longest prompt contained 2,266 input tokens. For
  distribution checks, each lane generated 500 responses for each of four
  prompts with temperature 1, top-k 20, top-p 0.95 and a six-token budget.
  AR used server seed 324161 and DFlash2 used 324299.

The tree server uses chain rounds for these sampled inputs. In the recurrent
comparison, all four failures came from the first sampling prompt. Output
positions 1, 3 and 4 and the joint pair 0–1 failed. The lowest p-value was
`1.20e-07` at position 3. The fused follow-up failed at positions 1–4 of the
first sampling prompt and position 5 of the third. AR itself matched one of
seven saved outputs between the B200 and RTX controls. The RTX comparisons
use an RTX AR reference.

## Runtime fixes

With an eager drafter, the tree builder tried to read a lattice from a missing
graph sampler. A tree round now requires fresh draft features from a graph
replay. An eager draft uses chain verification and the next round can select
tree again when the draft graph is available.

The fallback also uncovered a sampled chain width mismatch. Width-eight
verification consumed a width-16 eager draft and passed all 15 proposal rows
to a scatter expecting seven. The chain now keeps the candidate IDs and the
original proposal probabilities for the verified prefix. The anchor has no
proposal row. The width-specific graph path uses its original proposal rows.

The patched eager lane passed all seven same-route repeats and 15 mixed
requests. A forced eager drafter with target graphs enabled used the
width-eight chain CUDA graph for all 1,025 recorded verification rounds.
That lane passed 32 stress requests with five observed cancellations and
unchanged reference tokens after reuse. The patched graph-enabled recurrent
tree lane also passed stress and reproduced all seven outputs from the
pre-patch tree lane. The runtime fixes are in `b48eb90`.

## Numerical controls

The CUDA GDN fixture matched independent unpacked decode bit for bit at both
the output and state snapshot boundaries. Dense CUTLASS NVFP4 and Flash Next
MoE CUTLASS kernel controls also passed graph replay on SM120.

A synthetic attention test used the checkpoint's 24 query heads, four KV
heads and head dimension 256. With identical BF16 queries and FP8 KV histories,
FlashInfer's masked tree verify differed from individual AR decode on all 16
rows at prefix lengths 24, 2,048 and 2,266. The largest difference was
`0.0078125`. Treating the branches as separate sequences in a batched decode
matched all 48 rows exactly when both decode paths disabled KV splitting.
An eager full-model prototype with this grouped attention and recurrent GDN
matched three of seven outputs against the corresponding eager AR. The model
still had numerical differences with this attention control. In a trace at
the second prediction of frozen prompt 1 (zero-based), the input to layer 0
GDN was bit-identical. The outputs of the layer's QKVZ and BA projections
each had a maximum absolute difference of `0.03125`. The recurrent core
output differed by up to `1.52588e-05` and the GDN layer output by up to
`0.000244140625`. This difference was already present before the first
full-attention layer.

With deterministic inference, unfused projection/convolution and grouped
attention, two targeted prompts were identical for eight generated tokens
each. Extending that eager comparison to seven prompts with a 32-token
budget gave 3/7 exact matches. A graph-enabled deterministic control with
the standard FlashInfer attention path and recurrent GDN gave 2/7 for tree
and 3/7 for chain. Both the seven-prompt greedy gate and the independent
sampling gate remain open for the RTX configurations tested here.

The 105 CPU tests, engine contract check and six CUDA runtime checks passed
after the runtime fixes. The legacy CUDA checks passed 90 tree-mask cases and
the full fused GDN verification and state-commit fixtures for 9B and 27B.

The evidence directory `ax-engine-sglang-rtx-nvfp4-evidence-20261119/`
held launch manifests, exact input IDs, output IDs, sample metadata,
first divergences, stress counters and GPU telemetry. It was removed on
2026-11-19 after this report was recorded on main. The serving runs were
correctness checks. Utilization reached 100% during inference and dropped to
0% during some first-use CUDA compilation steps. All test processes exited
and GPU allocation returned to 0 MiB without a cgroup OOM event.
