1. Is Block-NCM sound?

Partly. Blocks solve fixed-length, and AR-verify gives a lossless fallback. But four risks are load-bearing.

VQ exactness: 99.9% per-token means block success is `0.999^B`. That is ~94% at B=64 and ~77% at B=256. Code needs exact match, so 6-23% of blocks need reject-and-fix. NCM's 98.8-100% was natural text, not code, and reconstruction is not generation accuracy. Expect worse under predicted codes.

Quality: parallel-in-level assumes conditional independence. Brackets, names, indentation violate that. NCM already lost 2.6 BLEU on WMT (22.6 vs 25.2) and needed 132 NFE with MBR to match AR. Code is stricter than MT.

DeltaNet: 30/40 Qwen layers are causal Gated-DeltaNet. Forward+backward with shared weights breaks the data-dependent recurrence. Also unclear what state gets committed for the next block. This is the highest architectural risk.

Speedup math: per block cost is ~K full-context passes vs B cheap cached AR steps. With K=8-12 and level-expansion (~3x positions), net gain vs optimized AR with MTP speculative decoding may be small or negative. NCM was only benchmarked vs diffusion.

2. Better choices

Tokenizer: drop 8192 x 8-12 levels. Use fewer levels and larger codebooks, e.g. B=64 with K=3-4 and lengths 8,16,64, codebook 16-32k. Better: skip VQ entirely and do block diffusion directly on tokens (LLaDA/Dream style). That removes the exact-reconstruction failure mode.

Block: start B=32-64, variable-length with EOS/pad. B=256 will drift and fail verification too often.

DeltaNet: keep it causal. Serialize levels coarse-to-fine; let full-attention layers use the block-parallel mask while DeltaNet scans causally over coarser levels plus earlier same-level tokens. Do not add a backward recurrence. If in-level context is needed, add a small zero-init dense-attention bypass around DeltaNet, not a weight-shared backward scan.

Reuse: freeze Qwen, train code projections, level embeddings, and per-level heads first. Consider a side network instead of surgery on all 40 layers.

3. Track A vs B: do A first

Yes, the split is right, but order matters: Track 0, then A, then decide on B.

Track 0 (days): benchmark Qwen3.6 in vLLM plus its existing 1 MTP layer as a speculative decoder. That is your free baseline. Add EAGLE-style AR drafter if needed.

Track A (weeks): 0.5-1B NCM drafter for frozen Qwen. Lossless, cheap, and it validates the tokenizer, block distribution, and verify loop. If acceptance is <2-3 tokens per verify pass, Block-NCM economics fail.

Track B only if A passes. B is a research conversion: 20-50B tokens, custom kernels, quality risk. Do not start B without A's tokenizer and acceptance data.

4. Hardware and compute

Use 8xH200 for v1. Reasons: mature flash-attention, FSDP, MoE Grouped-GEMM, and Gated-DeltaNet / FLA kernels; better RunPod availability and price; 8x141GB is enough with ZeRO-3 plus activation checkpointing. B200 has more HBM and FP8/FP4 throughput, but sm_100 support for FLA, flex-attention masks, and MoE kernels is the immature path. Audit kernels before any B200 run. Stay in bf16; FP8 MoE training risks quality for little schedule gain on one node.

Your arithmetic is right but optimistic: 30B x 3 x 6 x 3.5B ~= 1.9e21 FLOPs. Problems: 3x positions is a guess and grows with K; MoE all-to-all and custom masks lower MFU; tokenizer and ablations are extra. 25% MFU is high for hybrid MoE with custom masks. Plan for 12-20% MFU, so ~15-25 days on 8xH200, not 11. Single-node RunPod avoids inter-node networking pain, but confirm NVLink/NVSwitch topology, image with CUDA 12.4+, and large scratch for checkpoints.

5. Phased plan with go/no-go

Phase 0, baselines (1 week): vLLM AR throughput, MTP speculative speedup, HumanEval/MBPP/GSM8K. Go only if you can measure tokens/s at fixed quality.

Phase 1, tokenizer (2-4 weeks): train block VQ on Qwen-tokenized code/math/chat. Go: >=99.5% exact token match on held-out code and nested-decode works. No-go: switch to diffusion-on-tokens.

Phase 2, Track A drafter (4-6 weeks): small NCM drafter plus AR-verify. Go: >=2.5 accepted tokens per verify at T=0 and >=1.5x end-to-end speedup vs Phase 0. Else stop B.

Phase 3, B pilot (2-3 weeks, <=2B tokens, frozen backbone): causal-DeltaNet variant only. Go: gen-PPL within 5% of AR, HumanEval within 3 points.

Phase 4, full FT (one run): mixed NCM+AR loss, self-distilled data. Go: code/math within 2 points of Qwen3.6 and >=3x throughput at matched quality. Else ship Track A only.
