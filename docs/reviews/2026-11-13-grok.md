I'll ground the review in the NCM paper and the Qwen3.6 architecture before judging the Block-NCM proposal.Block-NCM is a reasonable research sketch and a poor first system to train. NCM's published wins are against diffusion language models at about 100M–725M parameters and fixed length ≤1024, not against a tuned autoregressive (AR) model. On WMT14 the paper's own AR baseline is ahead (BLEU 25.2 at 64 steps vs NCM 22.6 at 11). Qwen3.6 already has a one-layer multi-token prediction (MTP) head. Any drafter that does not beat MTP on accepted tokens per second is the wrong tool.

## 1. Soundness and failure modes

The block split is the right response to fixed length. The risky part is grafting a lossy code hierarchy and a non-causal mixer onto a causal hybrid MoE.

**Code reconstruction.** 99.9% token accuracy is one error per 1,000 tokens, which fails builds. NCM's 98.8–100% numbers are on small vocabularies; Sudoku hits 100% because the alphabet is tiny. Errors on a 248,320-way BPE (byte pair encoding) vocab concentrate on identifiers, numerals, and rare operators. Nested residual vector-quantized VAE (VQ-VAE) does not change that. A verify pass saves quality only if you reject the whole block or a prefix; it does not make the draft useful.

**Quality versus AR.** Within a level, codes are independent given the coarser reconstruction. Local syntax has to live entirely in the coarse codes. Conditioning corruption reduces exposure bias inside the block. It does not fix a bad plan. Across blocks, committing tokens and re-encoding them drifts from the code state the next block conditions on. Committing codes instead leaves the KV cache and the Gated-DeltaNet state in a different representation than the one you just sampled.

**DeltaNet.** Gated DeltaNet is a causal convolution (kernel 4) plus a causal delta-rule state. A backward scan is a second module. Copying the forward weights is not an initialization of the time-reversed process, and those kernels are not trained for it. The backward state must not be written into the cache. If it is, the next block and the AR verifier see a state no causal prefill would have produced. Treat any non-causal pass as draft-only, then replay the accepted tokens with the stock causal chunk kernel to update KV and recurrent state.

**Weight reuse.** Qwen has only ever seen token embeddings and partial mRoPE. Cumulative code reconstructions are a different stream. A frozen router over 256 experts of width 512 will not map that stream onto the features the experts expect. Adapters on the attention projections alone are unlikely to be enough.

## 2. Architecture changes

Make the last level the Qwen token ids, predicted by the existing LM head. Coarser levels are only a plan. Reconstruction error is then zero whenever the last level is accepted. That is the change that makes code viable.

Use B=32 first, lengths such as 4, 8, 16, 32 (K=4), not K=8–12 at B=256. NCM's cheap early steps disappear once every level rereads a long prefix on a 36B MoE; the win is fewer weight reads than B decode steps, and only while acceptance stays high.

Do not bidirectionalize DeltaNet. For the draft, either run the stock causal chunk kernel from the cached state, or skip DeltaNet inside the block and let the 10 full-attention layers attend to the prefix cache plus the block. Commit with one causal replay.

Keep the vision tower off. Leave MTP in place as the baseline drafter.

## 3. Track A versus Track B

Track A first, and only as a comparison against MTP and a same-FLOP EAGLE-style head, not against diffusion. A 0.5–1B drafter plus one Qwen verify pass is lossless and reads the 36B weights once per block. Track B does K forwards of the 36B model and still wants a verify pass, so it is slower unless you drop the verifier and accept quality loss. Full fine-tune is justified only after a small NCM drafter beats MTP on wall-clock at equal quality.

## 4. Hardware and the FLOP estimate

The product 30e9 × 3 × 6 × 3.5e9 = 1.89e21 is arithmetically right. H200 dense BF16 peaks near 989 TFLOPS, so 8× at 25% model-FLOP utilization (MFU) is about 11 days. That MFU is a dense-model figure. Experts are about 3.1M parameters (~6 MB in BF16); the step is bandwidth-bound. Plan on 10–15% MFU: about 20–28 days on 8×H200. The 3× position factor matches a square schedule only for B≈64 (1²…8² sums to ~3.2B). At B=256 and K=12 it is ~4.5×, and a mixed AR loss adds another full pass. Generating 20–50B distillation tokens was omitted: at 20k tokens/s aggregate that is 12–29 days before training starts.

Memory is about right: ~36B × (2+4+8) bytes ≈ 504 GB plus ~72 GB of BF16 gradients ≈ 580 GB. ZeRO-3 on 8×H200 (1,128 GB) fits with activation checkpointing. DGX-class B200 is 180 GB and ~8 TB/s, ~2.25 PFLOPS dense BF16, so ~2–2.5× if kernels are healthy, not a clean 5-day run. Some clouds label 192 GB; confirm the SKU.

Train in BF16. Hopper FP8 is mature; FP4 is an inference format. Causal Gated-DeltaNet prefill exists on Blackwell (cuDNN / FlashInfer, SM100), but backward and any bidirectional variant are not a reason to switch. Use 8×H200 until a full fine-tune is actually earned. RunPod B200 images still lag on PyTorch, grouped-GEMM MoE, and linear-attention backward; budget a kernel parity test before any multi-day job.

## 5. Phased go / no-go

**P0.** Reproduce upstream NCM at ~100M on one GPU. Go if reconstruction and generative perplexity land near the paper.

**P1.** Qwen-token tokenizer on code, math, and chat at B=32 and 64. Report exact-match overall and on identifiers, literals, and whitespace. Go if code-token accuracy ≥99.95%, or if you have already switched the last level to raw token ids. Stop on a lossy VQ below 99.9% on code.

**P2.** Train a 100–300M block generator, gold prefixes, frozen tokenizer. Go if a frozen Qwen's token negative log-likelihood on drafted blocks is within 0.15 nats of gold, or speculative accept length ≥8 at B=32.

**P3.** Track A against MTP and EAGLE at matched drafter FLOPs. Go only if wall-clock ≥1.5× MTP on code and chat at batch 1, with verifier-identical outputs. If MTP wins, NCM is the wrong drafter.

**P4.** Only then, LoRA or frozen-expert adapters for ~1B tokens. No-go on any cache mismatch (lossless mode must match untouched Qwen) or on more than a 2-point HumanEval / MATH drop.

**P5.** A 5B-token full fine-tune, not 20–50B, and only on H200 after P3 and P4. Ship criterion: pre-registered parity with base Qwen and ≥2× decode in the mode you will actually serve.
