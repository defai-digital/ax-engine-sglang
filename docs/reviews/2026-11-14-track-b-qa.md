# Track B decisive experiment: code QA (2026-11-14)

Reviewers: codex (gpt-6.1-sol) and Kimi (k3.1 pro), read-only, on `track_b/block_decode.py`,
`track_b/score.py`, `track_b/run_decisive.sh` and the checkers in `phase0/eval_quality.py`.
Both confirmed the token/cache recurrence of the decoder, the round accounting (every round commits
the accepted draft tokens plus one target token, also the first and the last round) and the
"x exact" ratio as a tokens-per-round ratio. Findings and what was done:

| # | Reviewer | Finding | Resolution |
|---|---|---|---|
| 1 | codex | `extract_code` dropped an unterminated code fence, scoring a truncated answer as empty | open fence is taken to the end of the text |
| 2 | codex | `run_python` could report a pass when the test process died silently | checker requires a `DONE_MARK` printed after the tests |
| 3 | codex | GSM8K took the last number of any text as the answer | answer must follow `####` |
| 4 | codex | EOS ids were hard-coded | read from the target's `generation_config` |
| 5 | codex | tokens cut by the budget or after EOS were counted as lossy tokens | clip first, count after |
| 6 | codex | rows of different experiments could mix in one directory | `settings.json` per policy directory, checked on resume |
| 7 | codex | a torn last row broke resume and scoring | `complete_rows` truncates it; the scorer stops at it |
| 8 | codex | a partial `ar` run narrowed the prompt set of every policy | `ar` never narrows; `exact` is the reference when `ar` is incomplete |
| 9 | Kimi | the scorer compared runs without checking that they share target, drafter and budget | scorer requires identical `settings.json` (except the policy) and prints them |
| 10 | Kimi | a `DONE` marker from a run with another `LIMIT` or model made the driver skip | the driver no longer looks at markers; `block_decode.py` validates settings and row coverage and returns before loading models when nothing is left |
| 11 | Kimi | `wait -n` reaped jobs that were waited for again (false `POLICY_FAILED`) | one worker per slot, a single `wait`, failures collected in a file |
| 12 | Kimi | the global job limit did not bound the jobs per GPU | slot s is bound to GPU s mod #gpus, at most `PER_GPU` each |
| 13 | Kimi | a crash while writing `settings.json` blocked resume | atomic write; an unreadable file without rows is recreated |
| 14 | Kimi | torn UTF-8 raised in the scorer's line iterator | rows are read as bytes and decoded inside the guard |

Effect on the reported run: the outputs were generated before fixes 4-6 and 9-14, which change
bookkeeping and resume behaviour, not the committed tokens (no output contains `<|endoftext|>`, so
the EOS change is a no-op here). `lossy_tokens` in the stored rows may count a few tokens beyond a
budget cut; the accuracy and tokens-per-round columns are unaffected. `settings.json` was written
afterwards from each directory's `DONE` record (same target, drafter and budget for all). All
scores in the report come from the fixed checkers (1-3). The partial `ar` run (5 HumanEval
prompts, killed for speed) is token-identical to `exact` on those prompts and was moved out of the
result root.

## Track C harness review (same day)

codex (gpt-6.1-sol) and Qwen 4 Max preview reviewed `track_c/train_joint.py`, `track_c/decode.py`,
`track_c/eval_system.sh` and the shared parts of `track_b`. Both confirmed the anchor / label /
position conventions between training and decoding, padding exclusion, the seeded validation
anchors, the adapter-disabled teacher, the save / load round trip and the cache snapshot + replay.

| # | Reviewer | Finding | Resolution |
|---|---|---|---|
| 1 | codex | resumed rows were reused for a different prompt file with the same ids | the prompt file's content hash is part of `settings.json` |
| 2 | codex | an empty train or val split (all rows filtered) looped forever or divided by zero | rejected after encoding |
| 3 | codex | `--device cpu` mixed bf16 taps with a float32 drafter (CUDA autocast is off on CPU) | autocast follows the device type |
| 4 | codex | the scorer divided by zero when `exact` emitted no token | ratio shown as `-` |
| 5 | Qwen | suspected: with gradient checkpointing and a frozen embedding the adapter might get no gradient | not the case here (the 40-step smoke run moved KL from 0 to 0.0015 and agreement to 0.99); a first-step check now aborts the run if the adapter receives no gradient |

## Agreement loss review

codex reviewed the agreement loss, `accept_self`, `trunk_argmax` and `--init-lora` in
`track_c/train_joint.py`. Confirmed: the miss indexing and its boundary cases, the ordering of the
supervised rows, the `on_path` shift, the teacher gate (original trunk) and detached targets, the
optimizer membership of a warm-started adapter. One finding: `--init-lora` was ignored with the
default `--lora-rank 0`; an adapter is now enabled whenever `--init-lora` is given.
