## Design review — ax-engine-sglang on Qwen3.8-27B

**Q1 — Ceiling.** Normalize to one AR step: speedup = L/(D+V), L = accepted tokens/round, D = draft cost, V = verify cost. Back out from the card: DFlash2 GSM8K 236.1/68.9 = 3.43× AR at L=5.46 → D+V=1.59; MTP 2.59× at L=5.02 → D+V=1.94 (7 sequential MTP steps). Verify is weight-bound: V≈1.2–1.4 for width 8–16. Even a free drafter (D=0) at L=5.46 caps at ~4.2× AR = 1.6× MTP. 3× MTP = 7.8× AR needs L≈11 at temp 1.0; SOTA is 5.46 and acceptance is entropy-limited. **3× MTP lossless is not reachable.** Realistic ceiling: L≈6.5–7 code / ~5 chat, D≈0.15–0.25, V≈1.3 → 4.3–4.8× AR = **1.6–1.85× MTP code, 1.5–1.7× chat**, assuming refinement/tree gains materialize. Keep the 1.5× gate; treat >1.8× as upside.

**Q2 — Architecture.** Do 1, 3, 4; cap 2 at two passes. (1) is the biggest fix: your 2.15 was on a 0.8B stand-in with a separate encoder; target-hidden conditioning is the proven cure for free-run collapse. (2) three passes cost ~0.3 t_AR and eat the gain — DFlash2 gets 5.46 in one pass + selector. (3) is cheap and the only way to pass c=32 (shrink width toward 0 as batch grows). (4) correct; top-k KL k≈10–20, include thinking traces at temp 1.0/top-p 0.95. Missing: tree verification (top-2 at positions 1–3, tree attention, ~+0.3–0.6 L at same V); reuse the target MTP head for token 1 (free); keep d=5120 (no projection bottleneck); don't reuse target DeltaNet states. **Concrete:** 6-layer full-attention transformer, d=5120, FFN 17408, ~2B; input = FC(concat of 5 tapped hiddens, layers 5/19/33/47/61) + accepted-token embeddings; pass 1 parallel 16 positions top-k, pass 2 refine; per-position confidence head; prefix-weighted CE + top-10 KL; own small KV over the accepted prefix.

**Q3 — NCM.** No. Your ablation: gold codes leak (2.0 TF → 0.07 FR), predicted codes 11–29% accurate. VQ adds a second compounding error surface; token space is the right granularity at temp 1.0. Keep "NCM" only as the parallel→refine schedule name. Coarse codes help only if they predict multi-token spans more reliably than tokens — no evidence; revisit only if Track A plateaus below 1.5×.

**Q4 — Build vs reuse.** Fine-tune DFlash2 (Apache-2.0, already trained on this exact target) with SpecForge or z-lab/dflash code. From-scratch with your chunk code means rewriting the encoder path and months of catch-up. Fastest path to beat DFlash2: init from its weights, add confidence head + adaptive width + 2-pass refinement + tree verify + MTP-token-1. Genuinely new: calibrated, batch-aware adaptive-width lossless drafting on a hybrid-GDN target — no public card does adaptive width.

**Q5 — Data/compute.** Use your measured ~10k tok/s/B200 distillation: 1B target tokens ≈ 28 GPU-h (~14h wall on 2 GPUs); 2B ≈ 56 GPU-h. Start 1B (thinking+non-thinking, code/math/chat, temp 1.0/top-p 0.95 + greedy). Hidden-state cache = 51 KB/token → 51 TB per 1B tokens: infeasible. Run the frozen target online during training (one no-grad forward yields hiddens+logits); cache only top-10 logits+indices (~60–100 GB/B tokens) or nothing. Compute: 54 GFLOP/tok target fwd + ~12 drafter fwd+bwd ≈ 66 GFLOP/tok; 1B tokens = 6.6e19 FLOP; 2×B200 at ~35% MFU ≈ 1.6 PFLOPS → ~12h wall (~24 GPU-h). Total ~55 GPU-h (1B) / ~110 (2B): inside budget. ~4–8k steps at 256k tokens/step, 1–2 epochs.

**Q6 — Track B.** Don't start. Block-8 in one 27B pass = 8× AR = 3.1× MTP only if quality holds at full parallel acceptance — it won't; 2–3 refinement passes cut it to ~2.7–4× AR ≈ 1–1.6× MTP with quality risk. Your own docs already call Track B unsupported. If forced: LoRA last-8 layers + block head on 50M tokens, measure HumanEval/MBPP/GSM8K vs base; kill if >2-point absolute drop or <4 effective tokens/pass. Defer until Track A ships.

**Q7 — Engine.** SGLang for benchmark and integration: DSpark/DFlash native, mature tree spec-decode. First verify it serves this target's MTP; vLLM has MTP built-in but DFlash only via unmerged PR 52816. All gate comparisons same-engine: run AR/MTP/DSpark/DFlash2/ours on SGLang. vLLM secondary only if production requires it.

**Q8 — Plan (go/no-go).**
1. Baselines + cost microbench (SGLang; AR/MTP/DSpark/DFlash2 at c=1,32; V at widths 4/8/16/32). Gate: ±10% of published. ~15 GPU-h.
2. Oracle adaptive-width study on DFlash2 logits (optimal policy vs fixed 8, offline). Decides item 3. ~2 GPU-h.
3. Pilot: DFlash2 + confidence head + 2-pass refinement, 200M tokens. Gate: free-run acceptance ≥5.8 GSM8K-like at ≤1.2× draft cost. ~20 GPU-h.
4. Full 1–2B training + SGLang integration (adaptive width, tree, MTP-token-1). Gate: ≥1.5× MTP code+chat c=1, ≥AR c=32. ~90 GPU-h + 30 eval.
5. Ablate/write up; if gate missed after 2 iterations, ship DFlash2+adaptive-width as the result. Track B deferred.

First three experiments = steps 1–3.

**Bottom line:** reset the 3× hope to 1.5–1.8× MTP lossless; condition on target hiddens, fine-tune DFlash2, and make adaptive width the contribution.
